# 浩宸信号

“浩宸信号”（Haochen Signal）是一个以“苏浩宸、狼王与信号场”世界观为交互语言的 AI 编程 CLI。

它计划提供持续式终端对话、项目文件编辑、Shell 与 Git 操作、技术资料检索，以及针对受限操作的独立 AI 自动审查。世界观负责命名和氛围，真实路径、命令、差异、错误和风险信息始终以清晰的技术形式呈现。

## 当前状态

项目正处于模块化实现阶段；当前已具备配置、会话、安全工具、模型流式适配、信号上下文与主代理工具闭环等基础能力。

- 产品名：浩宸信号
- npm 包名：`haochen-signal`
- 全局命令：`haochen`
- 运行环境：Node.js 20+
- 开发语言：TypeScript
- 模型协议：OpenAI-compatible Chat Completions
- 已实现：真实工作区路径边界、结构化文件补丁、受控命令执行、确定性边界守卫、隔离红眼审查与统一工具执行门
- 边界策略：路径越界和非公开网络目标直接拒绝；curl 主机覆盖会先规范化非标准 IPv4 再判定地址范围；通用 Git、env、curl 与 Shell 命令必须确认，固定专用只读 Git 工具可直接执行
- 上下文：追加式 JSONL 会话支持可重复压缩的历史摘要投影、真实最近事件保留及固定 token 预算截断
- 主代理：合并流式工具调用分片并按出现顺序执行，向模型如实回传工具失败，严格限制轮次与工具次数；非法 JSON 只允许修正一次，任一阶段中止都会有界退出并记录中断

## 设计目标

- 构建一个真正可用于项目开发的交互式 AI 编程代理。
- 让工作区内的常规操作顺畅执行，同时对受限操作进行独立的“红眼审查”。
- 支持任意兼容端点、自定义模型名、API 地址和请求头。
- 保留可替换的模型、工具、权限和会话模块边界。
- 同时生成正常发布版本与一个非压缩、包含运行依赖的超大单文件版本。

## 开发约定

- README、CHANGELOG 和项目说明使用中文。
- 正常源码保持模块化，超大单文件仅由构建流程生成。
- 敏感信息不得写入项目、会话或审计日志。
- 所有工具必须先通过结构校验、边界分类和必要的红眼审查或人工确认，再由统一执行门调用。
- 红眼审查模型由调用方显式指定；自动批准不得提高边界风险、扩大规范化范围或携带无法验证的执行约束。
- 工具执行前必须确认审计记录可追加；执行后的审计故障必须保留真实工具结果并附加警告，避免把已经发生的副作用误报为未执行。
- 主代理不会自动重试任何工具，尤其不会在修改性工具超时后重复执行；失败结果交由模型基于真实错误重新规划。
- 每次项目修改同步更新 CHANGELOG，并提交到 Git。
