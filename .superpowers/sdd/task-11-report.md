# Task 11 实现报告

## 结果

已实现 `runAgentTask(options)` 主代理状态机与系统提示，形成模型请求、工具执行、真实结果回传、重新规划和最终回答的完整闭环。

## 关键实现

- `src/agent/prompt.ts` 明确当前工作区与任务、注册工具边界、验证义务、不可信外部内容、权限隔离和技术证据展示要求。
- `src/agent/loop.ts` 合并同一索引的工具调用分片，等待当前模型响应结束，再按首次出现顺序逐个执行。
- 每个真实工具结果都会写入追加式会话，并以 `role: "tool"` 原样回传模型；失败不会伪装成成功，模型可在下一轮重新规划。
- 工具调用与模型轮次均采用无越界的计数语义：恰好用满工具预算仍允许后续最终总结，超过预算才停止溢出的调用。
- 首次非法工具参数 JSON 返回结构化 `INVALID_TOOL_ARGUMENTS`，第二次非法 JSON 立即停止，不执行工具。
- 模型流、会话读写和工具执行都与调用方中止信号竞争；即使依赖忽略信号，代理也会有界退出并尽力写入 `interrupted` 会话事件。
- 主循环不自动重试工具，因此修改性工具超时后不会重复产生副作用。
- `ToolRegistry.modelToolDefinitions()` 只读导出有效注册项的模型工具定义，避免主代理维护第二份工具清单。
