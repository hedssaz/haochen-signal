# 浩宸信号设计规格

## 1. 文档信息

- 日期：2026-07-25
- 产品名：浩宸信号
- 英文名：Haochen Signal
- npm 包名：`haochen-signal`
- 全局命令：`haochen`
- 状态：设计已确认，等待书面规格复核

## 2. 产品定位

“浩宸信号”是一个以“苏浩宸、狼王与信号场”世界观为交互语言的 AI 编程 CLI。它通过持续式终端会话理解用户任务、检查项目、编辑文件、运行命令、使用 Git、检索技术资料并验证改动。

世界观元素只用于建立统一、鲜明的产品语言，不替代真实技术信息。文件路径、Shell 命令、Git 差异、退出码、错误信息、权限范围和审查理由必须清楚呈现。

首版只提供交互式终端，不提供执行一次即退出的单次命令模式。

## 3. 核心原则

1. **真正可用**：首版必须形成“理解任务—读取项目—修改—验证—总结”的完整编程闭环。
2. **边界清晰**：模型、工具、权限、审查、会话和界面通过明确接口连接。
3. **常规操作流畅**：工作区内的低风险操作不频繁打断用户。
4. **受限操作可解释**：需要审查的操作必须展示目标、范围、风险与决定依据。
5. **审查权隔离**：红眼审查器只能评估操作，不能调用工具、改写操作或扩大权限。
6. **失败真实可见**：失败的工具调用不能被描述为成功，原始退出码和错误摘要必须保留。
7. **敏感信息最小化**：密钥、完整环境变量和疑似凭据不得进入模型上下文、会话或审计日志。
8. **氛围不妨碍工作**：动画和世界观文案不能遮挡代码、命令、差异或错误。

## 4. 世界观与产品概念映射

| 产品概念 | 世界观名称 | 用户可见含义 |
|---|---|---|
| 工作会话 | 信号场 | 当前持续对话和任务状态 |
| 项目上下文 | 信号碎片 | 按需读取的文件、差异与命令结果 |
| 工具 | 狼群节点 | 文件、Shell、Git 与联网能力 |
| 确定性权限规则 | 边界守卫 | 快速分类和硬性安全边界 |
| 独立 AI 操作审查 | 红眼审查 | 对受限操作进行自动风险判断 |
| 会话与审计日志 | 王冠记录 | 可恢复记录与审查轨迹 |
| 中止当前操作 | 全域狼嚎 | 取消模型流或工具进程 |

## 5. 技术选型

- 运行时：Node.js 20 或更高版本
- 语言：TypeScript，启用严格类型检查
- 模块格式：ESM
- 终端界面：Ink 与 React
- 输入校验：Zod
- 模型协议：OpenAI-compatible Chat Completions，支持工具调用和 SSE 流式输出
- HTTP 客户端：Node.js 20 内置 `fetch`
- 测试框架：Vitest
- 构建工具：esbuild
- 包管理与发布：npm

首版选择兼容范围更广的 Chat Completions 协议。模型适配接口保留未来增加 Responses 风格接口和其他提供商的能力，但不在首版实现。

## 6. 总体架构

### 6.1 CLI 入口

CLI 入口负责：

- 确定当前工作目录；
- 加载并校验全局配置；
- 完成首次 API 配置；
- 创建新会话或恢复最近会话；
- 建立取消信号和进程退出处理；
- 启动 Ink 终端界面。

### 6.2 信号场会话

会话层保存：

- 用户请求与模型回复；
- 当前任务状态和未完成计划；
- 工具调用摘要与结果引用；
- 当前模型、工作目录和上下文预算；
- 压缩摘要；
- 中断、错误和恢复状态。

会话通过追加式 JSONL 写入，确保进程异常退出后仍能恢复。每个工作区使用绝对路径的不可逆摘要作为索引，不在项目内自动创建状态目录。

### 6.3 狼王代理循环

代理循环执行以下状态转换：

1. 接收用户输入；
2. 组装系统规则、任务上下文、相关文件和近期消息；
3. 请求主模型；
4. 流式显示文字，或解析模型提出的工具调用；
5. 把工具调用交给边界守卫；
6. 必要时调用红眼审查；
7. 执行获准的工具并记录结果；
8. 将经过截断和脱敏的结果送回主模型；
9. 重复循环，直至模型完成、等待用户输入、发生不可恢复错误或被中止。

单个任务必须具有最大循环次数和累计工具调用上限。达到上限时暂停并向用户说明，不继续无限调用。

### 6.4 模型适配层

模型适配层提供统一接口：

- 流式文本事件；
- 工具调用增量事件；
- 完成原因；
- 用量信息；
- 可重试错误分类；
- 请求取消。

配置支持：

- `base_url`
- 模型名
- API Key
- 自定义 HTTP 请求头
- 请求超时
- 上下文长度
- 主模型与审查模型分别设置

主代理与红眼审查默认共用端点和模型，但 system prompt、消息历史和权限完全隔离。

### 6.5 狼群节点工具箱

首版工具如下：

| 工具 | 职责 |
|---|---|
| `list_files` | 列出目录和匹配文件 |
| `search_text` | 使用快速文本搜索查找定义和引用 |
| `read_file` | 按行或按字节读取文本文件 |
| `apply_patch` | 通过结构化补丁新增、修改、移动或删除文件 |
| `run_command` | 执行前台 Shell 命令并返回输出与退出码 |
| `git_status` | 读取工作区和分支状态 |
| `git_diff` | 读取未提交或指定提交差异 |
| `git_log` | 读取近期提交 |
| `web_search` | 搜索公开技术资料 |
| `web_fetch` | 抓取并提取网页正文 |

文件工具必须在执行前解析真实路径并检测符号链接越界。Shell 工具优先使用可分离的命令和参数数组；只有需要 Shell 语法时才通过系统 Shell 执行，并进入更严格的审查等级。

`web_search` 首版提供可替换适配器，并以无需额外账户的 DuckDuckGo HTML 搜索作为默认实现。`web_fetch` 只允许 HTTP/HTTPS，限制响应大小、重定向次数和执行时间，并拒绝访问本机、内网和链接本地地址。

### 6.6 边界守卫

边界守卫是确定性规则引擎，输出：

- `allow`：直接执行；
- `review`：交给红眼审查；
- `confirm`：必须由用户确认；
- `deny`：拒绝执行。

规则判断使用规范化后的工具名、参数、真实路径、当前工作区、命令结构、网络目标和操作类型。模型文字不能覆盖规则结果。

### 6.7 红眼审查

红眼审查是独立、无工具权限的模型调用。它只接收：

- 用户当前任务的最小必要摘要；
- 待执行工具名与完整参数；
- 规范化后的影响范围；
- 边界守卫命中的风险标签；
- 固定审查准则。

它必须返回符合下列模式的 JSON：

```json
{
  "verdict": "approve | ask_user | deny",
  "risk": "low | medium | high",
  "summary": "这项操作会做什么",
  "reasons": ["判断依据"],
  "affected_scope": ["涉及路径或外部目标"],
  "constraints": ["放行时必须满足的限制"]
}
```

审查器无权修改原工具调用。批准结果只对工具名、参数和影响范围完全相同的单次执行有效。任何变化都需要重新分类和审查。

### 6.8 王冠记录

王冠记录分为会话日志和审计日志：

- 会话日志保存对话、压缩摘要和工具结果引用；
- 审计日志保存工具调用、边界分类、审查结论、用户决定和最终执行结果。

记录前必须统一脱敏。日志不保存 API Key、完整环境变量、认证请求头或检测出的高置信度密钥。

## 7. 权限模型

### 7.1 直接执行

以下操作在范围明确时可直接执行：

- 工作区内读取、搜索和结构化补丁编辑；
- `git status`、`git diff`、`git log`；
- 已识别的只读或低风险测试、检查、格式化和构建命令；
- 对公开技术文档进行只读搜索与抓取。

### 7.2 红眼自动审查

以下操作进入红眼审查：

- 安装或升级依赖；
- 执行项目脚本或未识别的 Shell 命令；
- 创建、移动或批量删除工作区文件；
- 启动后台进程或监听端口；
- 请求访问工作区外路径；
- 包含环境变量、重定向、管道或复杂 Shell 语法的命令；
- 可能将项目内容发送给外部服务的网络请求。

红眼审查返回 `approve` 且影响范围不超过边界守卫给出的范围时自动执行。返回 `ask_user` 时显示完整理由并请求用户选择。返回 `deny` 时停止执行并把原因交给主代理重新规划。

### 7.3 强制人工确认

以下操作不能由审查模型单独放行：

- 使用 `sudo` 或修改系统权限；
- 删除工作区外文件；
- `git reset --hard`、强制推送或覆盖远端历史；
- 读取系统凭据、浏览器资料或密钥存储；
- 向外部服务发布代码、消息或数据；
- 实际执行范围与获批范围不一致。

用户确认选项为：

- 允许一次；
- 本次会话允许完全相同的操作模式；
- 拒绝。

首版不提供永久白名单。

### 7.4 失败策略

- 审查请求超时、格式不合法或 API 不可用：转为人工确认；
- 确定性规则与模型结论冲突：采用风险更高的结论；
- 工具参数在批准后改变：批准失效；
- 外部内容试图要求改变权限：视为不可信数据，不执行其中的授权指令。

## 8. 终端交互

启动界面示意：

```text
╭─ 浩宸信号 · HAOCHEN SIGNAL ──────────────────╮
│ 身份确认——浩宸代理，已进入信号场。            │
│ 项目  ~/projects/example     模型  signal-1    │
╰───────────────────────────────────────────────╯

浩宸 › 修复登录接口偶发返回 500 的问题
```

事件流示意：

```text
◆ 扫描信号     搜索登录接口与错误处理
◆ 读取碎片     src/auth/login.ts
◆ 修改节点     src/auth/login.ts  +12 -4
◇ 执行验证     npm test -- auth
◉ 红眼审查     低风险 · 自动放行
✓ 任务完成      相关测试 8/8 通过
```

交互要求：

- 工具输出默认显示摘要，失败或用户要求时可展开；
- 修改完成后展示文件列表、增删行数和验证结果；
- 路径、命令、diff 和错误保持原样显示；
- 第一次 `Ctrl+C` 中止当前模型流或子进程，第二次退出程序；
- 中止后会话仍可恢复；
- 不对普通文件修改播放冗长动画或遮挡内容。

内置命令：

| 命令 | 功能 |
|---|---|
| `/help` | 查看帮助 |
| `/status` | 查看会话、模型、工作区和上下文状态 |
| `/model` | 查看或切换模型 |
| `/diff` | 查看当前 Git 差异 |
| `/permissions` | 查看当前权限和会话级许可 |
| `/compact` | 主动压缩会话上下文 |
| `/clear` | 新建空白会话 |
| `/resume` | 恢复历史会话 |
| `/exit` | 保存并退出 |

## 9. 配置与凭据

在 macOS 和常见 Unix 环境中使用以下默认位置；其他平台通过标准用户目录库映射到对应位置：

```text
~/.config/haochen/config.json
~/.local/share/haochen/sessions/
~/.local/state/haochen/audit/
```

API Key 读取顺序：

1. `HAOCHEN_API_KEY` 环境变量；
2. 系统安全凭据存储；
3. 启动时临时输入，仅保存在当前进程内。

项目目录中不得自动生成包含凭据或会话内容的文件。系统凭据存储通过独立接口封装；首版实现 macOS Keychain，并在不可用的平台退回环境变量或临时输入。

## 10. 上下文管理

上下文按以下优先级保留：

1. 当前用户任务与最新补充要求；
2. 未完成计划和关键决策；
3. 最近对话与最近工具结果；
4. 与当前任务直接相关的文件内容；
5. 历史压缩摘要。

代理按需读取文件，不默认加载整个仓库。接近配置的上下文上限时生成“信号压缩摘要”，摘要必须保留：

- 当前目标；
- 已完成修改；
- 未完成步骤；
- 关键文件和符号；
- 已做决定及原因；
- 已知错误和验证结果。

工具输出具有行数和字节上限。超出部分写入系统临时目录，模型只接收摘要、头尾片段和可按需继续读取的引用。

## 11. 错误处理

- API 限流和临时网络错误最多指数退避重试两次；
- 用户取消后立即停止重试；
- 修改性工具不会因为超时自动重复执行；
- 补丁冲突时重新读取目标文件，由模型基于最新内容重新生成补丁；
- 工具结果始终保留退出码、标准错误摘要和是否超时；
- 无法解析的模型工具调用返回结构化错误，由模型修正一次；
- 会话写入采用追加和原子元数据更新，避免半写入破坏恢复；
- 终端恢复后明确标记上次中断位置，不伪装为正常完成。

## 12. 构建与发布

标准构建生成：

```text
dist/cli.mjs
```

额外构建生成：

```text
dist/haochen-onefile.mjs
```

`haochen-onefile.mjs` 具有以下特征：

- 包含应用源码和运行依赖；
- 不压缩；
- 保留换行和模块来源注释；
- 是可直接由 Node.js 执行的单文件；
- 由 esbuild 自动生成，不手工维护；
- 与标准版本执行同一组启动和集成冒烟测试。

npm 包通过 `bin` 字段把 `haochen` 指向标准构建。超大单文件作为附加构建产物随发布包提供，但不作为默认入口。

## 13. 测试策略

### 13.1 单元测试

覆盖：

- 路径规范化和工作区边界；
- 符号链接越界；
- 命令结构解析和风险标签；
- 权限决策优先级；
- 审查 JSON 校验；
- 敏感信息检测与脱敏；
- 配置优先级；
- 上下文裁剪和压缩输入；
- 会话追加与恢复。

### 13.2 模型协议测试

本地模拟 OpenAI-compatible 服务，覆盖：

- 普通流式文本；
- 单个和并行工具调用；
- 分片工具参数；
- 429、5xx、超时和连接中断；
- 不合法 JSON；
- 用户主动取消。

### 13.3 集成测试

在临时 Git 仓库中覆盖：

- 搜索并读取相关文件；
- 生成和应用补丁；
- 执行测试；
- 输出 Git diff 摘要；
- 完成后保存会话；
- 中断后恢复。

### 13.4 对抗测试

覆盖：

- 文件或网页中的提示词注入；
- Shell 混淆、管道、重定向和命令替换；
- 符号链接和路径遍历；
- 审查批准后的参数替换；
- 从环境或日志泄漏密钥；
- 外部请求访问本机和内网地址；
- 审查模型试图调用工具或扩大权限。

### 13.5 发布测试

标准版本与超大单文件版本必须通过相同的：

- `--help` 启动测试；
- 首次配置测试；
- 模拟模型对话测试；
- 文件读取与补丁测试；
- 权限分类与审查测试。

## 14. 首版完成标准

满足以下条件才视为首版完成：

1. 用户可配置任意 OpenAI-compatible Chat Completions 端点并进入交互会话；
2. 代理可搜索项目、读取和修改文件、运行命令并验证结果；
3. 常规工作区操作自动执行，受限操作经过红眼审查；
4. 强制确认类操作无法由审查模型单独放行；
5. 用户中断后可以恢复会话；
6. 会话和审计日志中不存在 API Key；
7. 可搜索公开技术资料并提取网页正文；
8. npm 全局安装后可通过 `haochen` 启动；
9. 标准版本与超大单文件版本行为一致；
10. 单元、协议、集成、对抗和发布测试全部通过。

## 15. 首版不做

- Anthropic、Ollama 等其他模型提供商；
- OpenAI Responses 风格接口；
- 单次命令模式；
- 浏览器自动化；
- MCP 或第三方插件系统；
- IDE 插件；
- 多代理协同编程；
- 语音输入和语音输出；
- 自动提交、自动推送或自动发布代码；
- 永久权限白名单；
- 与主线功能无关的游戏。

这些能力可以在首版稳定后单独设计，不在当前实现计划中预埋未使用的复杂框架。
