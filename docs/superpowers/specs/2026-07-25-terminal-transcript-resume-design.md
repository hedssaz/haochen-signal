# 浩宸信号终端分区与工作区会话恢复设计

## 目标

改造浩宸信号的交互层级，使用户输入、代理发言、工具调用、工具结果和任务状态一眼可分；同时让 `/resume` 直接列出当前工作区的全部会话，用户无需手输 ID。

## 终端信息分区

采用紧凑分区，不为每条记录绘制完整大卡片，避免长任务过度占用终端高度。

- 用户输入使用 `你 ›` 标题。
- 代理的中间说明与最终回答使用 `浩宸 ›` 标题。
- 工具调用使用 `工具 › <工具名>` 标题，下一行显示 `参数  <摘要>`。
- 执行门使用 `审批 › <工具名>` 标题，明确显示是否需要审批、决策者和结果。
- 工具结果使用 `结果 › <工具名>` 标题，并明确显示成功或失败。
- 审查、错误和普通状态分别使用独立的 `审查 ›`、`错误 ›`、`状态 ›` 标题。
- 各分区使用不同颜色，并在相邻分区之间保留空行。

代理流式文字不直接逐字符追加终端记录；收到稳定的代理消息事件后，再创建一条代理分区。最终回答不得再与工具成功标记共用前缀。

## 工具参数摘要

工具调用行显示真实工具名和单行参数摘要。摘要必须先调用现有递归脱敏器，再执行长度与结构限制。

- 普通对象序列化为单行 JSON，最长 240 个可见字符。
- `apply_patch` 仅显示操作类型、数量和目标路径，不显示补丁正文。
- `run_command` 显示命令、缩略参数和工作目录；环境变量整体显示为 `[REDACTED]`。
- 数组和长字符串按固定上限截断，并使用 `…` 标记。
- 无法序列化的参数显示 `[无法摘要]`，不得影响工具执行。
- API Key、认证头、Cookie、令牌、私钥和凭据 URL 必须继续显示为 `[REDACTED]`。

工具结果沿用工具返回的脱敏摘要，不重复输出完整数据。

## 审批过程与结果

每次工具调用都必须生成一条可见的执行门结论，包括无需 AI 审查的低风险操作。终端用语与真实决策路径一一对应：

- 确定性边界直接放行：`无需 AI 审查 · 边界直接放行`
- 确定性边界拒绝：`边界拒绝 · <简短理由>`
- 进入红眼审查：先显示 `AI 自动审查中`
- AI 批准：`AI 自动审查通过 · <风险> · <摘要>`
- AI 拒绝：`AI 自动审查拒绝 · <风险> · <摘要>`
- AI 要求人工确认或审查失败：`AI 审查转人工确认 · <摘要>`
- 用户选择：`用户仅本次允许`、`用户允许本会话` 或 `用户拒绝`
- 命中已有会话许可：`本会话许可命中 · 无需重复审查`
- 执行前复核发现范围漂移：`执行前复核拒绝 · 操作范围已变化`

“直接放行”不得写成“审批通过”，避免让用户误以为 AI 已参与。AI 结论显示审查风险与摘要，但不展示内部提示词。人工选择完成前，现有确认面板继续显示确定性范围、理由和可选按键。

执行门新增只读的结构化事件报告器。`ToolRegistry` 在分类、AI 审查、人工确认和执行前复核的关键节点发送事件；CLI 订阅后更新审批分区和持续状态。报告失败不得改变执行决策，审计 JSONL 仍是持久化事实来源。

## 持续运行状态

只要主任务仍有活动的 `AbortController`，输入框上方持续显示一条状态：

```text
状态 › 运行中 · <当前阶段> · Ctrl+C 中止
```

阶段随事件变化：

- 刚提交任务：`正在理解任务`
- 收到代理文字：`正在规划`
- 工具开始：`正在调用 <工具名>`
- 红眼审查：`正在审查 <工具名或操作>`
- 等待人工确认：`等待确认 <工具名>`
- 工具结束：`正在整理结果`

任务完成、失败或中止后，持续状态立即消失。任务运行时仍允许键入，但按回车不会启动第二个任务，并显示明确提示。

## 工作区会话归属

新增会话元数据事件，记录：

- 会话 ID
- 创建时间
- 当前工作区绝对路径的 SHA-256 摘要

不把真实工作区路径写入会话文件。新会话必须在主界面渲染前写入一次元数据。现有旧会话没有该事件，归为“工作区未知”，不得猜测其归属。

`SessionStore.list` 返回选择器所需的安全摘要：

- 会话 ID
- 最近更新时间
- 第一条非空用户输入的缩略预览
- 工作区摘要或“未知”

列表仍按最近更新时间降序排列。损坏会话保持现有严格读取语义，不因选择器而静默跳过结构错误。

## `/resume` 交互选择器

不带参数执行 `/resume` 时：

1. 读取全部会话摘要。
2. 主分组只显示工作区摘要与当前工作区一致的会话。
3. 第二分组显示旧版“工作区未知”会话，保证旧数据仍可访问。
4. 使用 `↑`、`↓` 移动选择，`Enter` 恢复，`Esc` 取消。
5. 列表超过终端窗口时只渲染围绕当前选择项的固定窗口，但所有条目均可访问。

每项显示更新时间、首条用户输入预览和短 ID；完整 ID 不作为主要交互内容。`/resume <ID>` 保留，用于脚本和高级操作。

恢复成功后关闭选择器、切换活动会话，并显示恢复结果。选择器打开期间不接受普通任务输入；待确认操作的按键处理优先级高于会话选择器。

## 数据流与组件边界

- `sessions/types.ts` 定义向后兼容的会话元数据事件和扩展后的会话摘要。
- `sessions/store.ts` 负责写入元数据、按工作区分类并生成预览。
- `cli/tool-summary.ts` 只负责安全参数摘要，不依赖 React。
- `tools/registry.ts` 通过结构化报告器公开确定性分类、AI 审查、人工选择和执行前复核结果。
- `cli/reducer.ts` 将代理事件映射为具有明确类别的终端记录，并维护活动状态。
- `cli/app.tsx` 负责分区渲染、持续状态和会话选择器按键交互。
- `cli/index.tsx` 计算当前工作区摘要、初始化新会话元数据，并接线列表与恢复操作。

## 错误处理

- 参数摘要失败时显示 `[无法摘要]`，工具执行继续。
- 会话元数据写入失败时不启动交互界面，避免创建无法归类的新会话。
- 会话列表为空时显示“当前工作区没有可恢复的会话”。
- 恢复目标在选择后被删除或损坏时，保留当前会话并显示错误。
- 旧会话只能标记为未知，不自动迁移到当前工作区。

## 测试

- 参数摘要覆盖脱敏、截断、补丁结构、循环引用和无法序列化值。
- 执行门测试验证直接放行、边界拒绝、AI 批准、AI 拒绝、转人工、用户选择、会话许可和范围漂移均产生准确且不误导的可见结论。
- reducer 测试验证用户、代理、工具、结果、状态和错误使用不同类别。
- Ink 测试验证持续运行提示在任务期间存在并在完成后消失。
- Ink 测试验证会话选择器的分组、方向键、回车和 Esc。
- SessionStore 测试验证工作区过滤、预览、排序、旧会话分类与向后兼容。
- 集成测试验证新会话写入元数据后能由同一工作区列出，另一工作区不可见。
- 真实 TTY 验收验证长参数不会破坏布局，工具调用和最终回答具有清晰边界。
