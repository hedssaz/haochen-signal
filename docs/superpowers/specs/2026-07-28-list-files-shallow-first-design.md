# 文件列表浅层优先设计

## 目标

`list_files` 继续最多返回 500 个文件，但大型工作区截断时优先保留入口、配置、说明文档等浅层文件，避免深层目录按字典序抢占全部名额。

## 排序与截断

- 文件深度以请求目录为基准；请求目录中的直接文件深度为 0，其直接子目录中的文件深度为 1，依此类推。
- 递归遍历按广度优先进行：先收集当前层文件，再进入下一层目录。
- 同一深度的文件按完整工作区相对路径字典序排列，保证结果稳定。
- 收集到第 500 个文件后停止；因此超限时自然优先舍弃更深层文件。
- 显式请求单个文件以及排除目录、符号链接、取消和工作区边界规则保持不变。
- 返回结构和“已截断”提示保持不变。

## 方案取舍

- 不提高 500 的输出上限，避免增大模型上下文和终端输出。
- 不为 README、配置文件等名称建立特殊白名单，避免项目类型偏见。
- 采用统一的目录深度规则，使任意子目录作为 `path` 时也获得相同语义。

## 验证

- 构造浅层文件和超过 500 个深层文件，验证浅层文件始终保留。
- 验证不同目录内同一深度的文件按完整相对路径稳定排序。
- 验证恰好 500 个文件不标记截断，第 501 个文件才标记截断。
- 运行完整测试、类型检查和构建。
